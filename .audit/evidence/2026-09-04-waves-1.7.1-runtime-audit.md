# Waves 1.7.1 runtime audit status

Updated September 5, 2026. The collector subtask is verified. The runtime
audit and release qualification remain incomplete.

## Scope

Added a bounded process sampler, Time Profiler collection, an evidence
analyzer, focused tests and operating instructions. Both the runtime and
existing launch parser suites now run in the shared infrastructure gate.
No app source, realtime callback, audio control or release metadata changed
in this subtask. The app-source checkpoint remains `4c9176d`.

The collector binds the target to its PID, executable path, hash and process
start. It uses private output directories, preserves failed samples, and
does not collect Waves diagnostics exports or system-wide logs. Missing
metrics remain unavailable. Raw traces and their table-of-contents exports
are private, unsanitized files that must not be staged.

## Review and tests

Independent review by `runtime_collector_review`, GPT-5.6 Sol with low
reasoning, found identity, coverage, deadline, trace validation and timing
gaps. Three scoped fix rounds addressed them. The final review approved the
collector with no open findings.

Controller verification on the final tooling passed 19 runtime tests with
124 assertions in 38.380030 seconds. The unchanged launch parser suite passed
13 tests with 92 assertions. Bash and Ruby syntax, shellcheck and diff checks
passed. The implementer also ran the existing release infrastructure suite,
107 tests with 996 assertions, and deadline suite, two tests with five
assertions, before the collector review rounds. Those latter results are not
fresh full-gate evidence for the final collector revision.

Tests cover malformed and missing identity, missing and invalid metrics,
failed tool status, clustered soak samples, insufficient coverage, callback
deadline violations, overloads, failed or invalid traces, delayed readiness,
and cleanup of a TERM-resistant recorder. No test substitutes for actual
audio stress or a two-hour soak.

## Native tool verification

Full Xcode 27.0 build 27A5252f was selected per command. Global xcode-select
was unchanged. A direct two-second trace against an owned C process took
58.52 seconds to start, record and save. Its table-of-contents export took
11.96 seconds. These observed costs exposed overly short collector bounds.

The final collector waits for xctrace's Darwin start notification before
numeric sampling. Template discovery allows 45 seconds. The recorder has
one absolute deadline of requested duration plus 90 seconds, including
startup and saving. TOC export allows 45 seconds. The entire collector has
a requested-duration-plus-210-second bound. Fast sampler, file and XML
checks retain five-second limits. These are tool deadlines, not performance
qualification thresholds.

The controller then ran the final collector against a newly compiled owned
C executable that only sleeps. With a two-second request and one-second
sample interval, it recorded three samples over 3.052600 seconds with no
sample failures. Total command time was 73.07 seconds. Time Profiler reported
`recorded`, `recordingStartSynchronized: true` and `tocValidated: true`.
The analyzer correctly reported `incomplete` for the unavailable runtime
metrics and insufficient soak duration. No test or recorder process remained.

## Open gates

The installed Waves baseline still needs the prescribed scenario matrix and
30 cold-launch observations. Candidate measurements must use the final signed
bytes. Callback duration, buffer deadline, overloads, wakeups, dirty memory
and retained-controller metrics remain unavailable to this collector.
Source callback checks do not prove runtime deadlines. No CPU, memory,
energy, startup or audio-quality improvement is claimed.

Security audit completion, Half Bounce qualification, the two-hour candidate
soak, recovery and shutdown measurements, signing, notarization, physical
Mac mini testing and publication all remain open.
