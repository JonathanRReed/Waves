# Waves 1.7.1 Security and Pull Requests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve every open Waves pull request through tested integrated fixes or evidence-backed closure, then complete a deep security audit with no unresolved critical, high, or relevant medium finding.

**Architecture:** Keep `origin/main` as the source of truth and treat each pull request as an untrusted proposal. Land narrow tests and fixes on `codex/waves-1.7.1` in runtime-risk order, then audit the combined tree and record each validated or rejected finding under `.audit/`.

**Tech Stack:** Swift 6, Swift Testing, Core Audio, Unix domain sockets, Ruby/Minitest, Bash, GitHub Actions, Sparkle 2.9.5.

**Spec:** `docs/superpowers/specs/2026-09-04-waves-1.7.1-release-design.md`

## Global Constraints

- Preserve the 250 ms application termination bound, Wave Link ownership rules, realtime callback constraints, and the current external-control protocol.
- Do not merge pull-request branches. Reproduce each security goal against this branch, then implement the smallest complete combined change.
- Add a decision-log row for every PR before closing it. Closing a PR and posting its evidence happen only after the integrated commit is pushed.
- Run focused tests first. Run `swift test` and `/usr/bin/ruby script/tests/release_infra_test.rb` after each subsystem.
- Do not log app names, device names, profile names, audio content, socket payloads, or persisted values.

- [ ] Replace the blocking accept loop with a bounded proof loop. It may drain verified same-user backlog entries, but it must stop on `EAGAIN` or a monotonic deadline and close every accepted descriptor.

  else if errno != EINTR { return false }
}
