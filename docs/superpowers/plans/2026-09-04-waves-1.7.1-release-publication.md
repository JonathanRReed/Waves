# Waves 1.7.1 Release and Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce one exact Waves 1.7.1 build 19 artifact, verify it locally and on the physical Elgato Mac mini, then publish identical bytes through GitHub, Sparkle, the website, and Homebrew.

**Architecture:** Update canonical metadata once, merge only a green reviewed release branch, build from a clean exact `origin/main`, seal all candidate evidence before remote testing, create and validate a signed exact-revision tag, and compare uncached public artifacts to the sealed candidate.

**Tech Stack:** SwiftPM, Bash, Ruby, codesign, notarytool, stapler, spctl, Sparkle, Git/GitHub CLI, GitHub Actions, private Stream Deck companion repository, Homebrew cask, Waves website deployment.

**Spec:** `docs/superpowers/specs/2026-09-04-waves-1.7.1-release-design.md`

## Global Constraints

- Release version is 1.7.1 and build is 19. Do not change bundle ID, minimum macOS, Developer ID identity, Sparkle public key, or receipt issuers.
- Any candidate-byte change invalidates signing, notarization, local QA, Mac mini QA, tag envelope, and publication evidence.
- Neither Mac mini checkout is release source. Transfer only the sealed candidate and a separately verified companion package.
- Do not push a tag or publish assets until the local signed tag passes the publication gate.
- Do not publish the Half Bounce social post without final user approval.
