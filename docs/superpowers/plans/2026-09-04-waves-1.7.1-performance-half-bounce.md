# Waves 1.7.1 Performance and Half Bounce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure and improve Waves launch and whole-app performance, then demonstrate a backend-confirmed mute or volume change before the Dock icon settles on at least 29 of 30 controlled cold launches.

**Architecture:** Add privacy-safe monotonic milestones at lifecycle and store boundaries, keep realtime code untouched by instrumentation, compare installed 1.7.0 build 16 with the exact 1.7.1 candidate, and move only measured nonessential work out of control readiness.

**Tech Stack:** Swift 6, Swift Testing, OSLog signposts, Core Audio, `xctrace`, `powermetrics`, Activity Monitor sampling, shell/Ruby evidence tooling, screen recording.

**Spec:** `docs/superpowers/specs/2026-09-04-waves-1.7.1-release-design.md`

## Global Constraints

- A successful interaction requires backend-confirmed completion. First paint, slider movement, queued work, or a hidden loading state does not count.
- Never instrument a realtime callback. Never log app, device, profile, audio, or persisted-data identifiers.
- Use identical hardware, OS, preferences, route count, and scenario order for 1.7.0 and 1.7.1 comparisons.
- Investigate any comparable CPU or memory regression of 5 percent or more, monotonic growth, callback deadline miss, overload, or audible glitch.
