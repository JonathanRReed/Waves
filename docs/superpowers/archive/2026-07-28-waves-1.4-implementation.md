# Waves 1.4 Implementation Plan

> Historical shipped plan. Waves 1.4 has been released. Version 1.4.4 remains
> the latest published build while Waves 1.5 is in development.

Design: [2026-07-28-streamdeck-hotkeys-design.md](../specs/2026-07-28-streamdeck-hotkeys-design.md)
Regression floor: [2026-07-28-feature-inventory.md](../specs/2026-07-28-feature-inventory.md)
Baseline: `625f7e3` (1.3.1 + design)

Four tracks, in dependency order. Each phase ends green: `swift build`,
`swift test`, and no change to any capability in the feature inventory.

## Track D — Snow Leopard pass

Landed first so the feature work is written against clean code.

### Phase D1: Direct manipulation

1. Add `pendingVolumeDebounceTasks` alongside `pendingEqualizerDebounceTasks`.
2. Schedule an ~80 ms trailing transaction from `setDesiredVolume` with
   `persistencePolicy: .none`, `feedbackPolicy: .none`, `optimistic: false`.
3. Skip the intermediate transaction unless the app is already `.managed`, so a
   mid-drag helper process can never trigger a tap rebuild and an audible dropout.
4. Leave `commitDesiredVolume` as the only persisting, toast-bearing boundary,
   and cancel any in-flight debounce there.
5. Register the new tasks in `drainAppIntentTransactions` and
   `trackedAppIntentTaskCount`.
6. Add an optimistic projection to profile apply.
7. Kick a level poll when the menu-bar panel opens.
8. Tests: intermediate applies happen during a drag; audio moves before mouse-up;
   only the commit persists; drain covers the new tasks.

### Phase D2: Launch feel

1. Render the mixer as the first frame when privacy and guided setup are complete
   and a restored session exists; reserve `PrivacySetupSurface` for
   `.awaitingPrivacy`, `.savingConsent`, `.startupFailed`.
2. Gate the "Refreshing" pill on `store.isLoading || !store.isAudioRunning` so the
   early mixer still reads as warming up.
3. Dim controls while `startupState != .running` instead of firing a
   "Finish setup" toast on an early click.
4. Delete the no-op `session = warmSnapshot` self-assignment.
5. Make `reapplyRestoredAudioState` concurrent and move it off the startup gate.
6. Defer diagnostics, capture authorization and full device enumeration until
   after the mixer is interactive.
7. Cache encoded icons on disk keyed by bundle id + mtime.
8. Tests: first frame is the mixer for a returning user; startup order.

### Phase D3: Theme and craft

1. Give `MixedWaveformView` `@Environment(\.wavesTheme)` and thread it into
   `draw`; baseline from `theme.hairline(increasedContrast:)`, sum colours from
   `theme.accentGradientColors`.
2. Replace hardcoded white/black opacities on the four offending surfaces with
   theme tokens.
3. Unify list row insertion/removal animation between the main window and the
   menu bar; animate the menu-bar section alongside its rows.
4. Animate the EQ chip row's reflow.
5. Give the mixer row's twin control a hover state; separate the hover colour
   from the selection colour.
6. Fixed-width toolbar slots and monospaced digits to stop horizontal shifting.
7. Tests: rendered-UI smoke across light/dark × both palettes stays green;
   contrast assertions on the waveform's resolved colours.

### Phase D4: Steady-state and memory

1. Cache `visibleApps` with an explicitly enumerated invalidation set; make
   `invalidateVisibleAppsCache()` real.
2. Store the folded sort key on `AudioApp` instead of folding per read.
3. Derive the accessibility rotor from one evaluation.
4. Change-gate the four `@Observable` writes in the 8 s tick and the
   `session.json` rewrite.
5. Extend the capture-authorization early-out to cover the idle, nothing-routed
   case.
6. Give `AppIconCache` a `countLimit`, a cost function, and eviction on app exit.
7. Remove `iconTIFFData` from `AudioApp`'s `Codable` surface so no future change
   can persist icon blobs.
8. Tests: cache invalidation correctness (the risky part — a wrong cache is worse
   than none); no redundant observable writes; icon cache bounds.

### Phase D5: Carried-forward items

1. Prune dead Core Audio object IDs, reworking `matches`/`covers` together.
2. Unify persistence store names and dedupe at the reporting boundary.
3. Bound the synchronous shutdown-report write with a deadline.
4. Tear down stores in test fixtures.
5. Cover `LevelMeterModel` ballistics.

## Track A — Control surface

### Phase A1: Protocol core

1. `ControlProtocol`: request/response/event codec, versioning, error codes.
2. `ControlCommand` handler over `AppStore`'s existing entry points — no bypass of
   the intent/generation machinery.
3. Pure tests: codec, unknown command, oversized line, version mismatch.

### Phase A2: Socket server

1. `ControlServer`: listener, accept loop, per-connection line framing.
2. `getpeereid` uid check; size caps; rate limit; connection cap.
3. Stale socket detection and replacement; unlink on shutdown.
4. `enableExternalControl` preference, default off, Settings ▸ Advanced.
5. Subscription fan-out for state pushes.

### Phase A3: wavesctl

1. A small CLI target speaking the protocol.
2. Documented in `docs/RELEASE.md` as the pre-hardware verification path.

## Track B — Per-app mute hotkeys

### Phase B1: Mechanism

1. `HotkeyCenter` on Carbon `RegisterEventHotKey` + `InstallEventHandler`.
2. `HotkeyBinding` model and persistence.
3. Migrate the three existing frontmost shortcuts as editable defaults.
4. Remove the `NSEvent` monitors.
5. Tests: model, conflict detection, migration.

### Phase B2: Interface

1. Settings ▸ Shortcuts binding list with a recorder per row.
2. "Add app shortcut" app picker.
3. Mixer row context menu entry.
4. Inline conflict messaging on registration failure.

## Track C — Stream Deck plugin

### Phase C1: Scaffold

1. `streamdeck create` scaffold under `streamdeck/`.
2. `manifest.json`: SDKVersion 3, Node 24, two actions, `$B1` encoder layout.
3. Icons and images at both scale factors.

### Phase C2: Client and actions

1. `waves-client.ts`: framing, request/response correlation, subscription,
   capped exponential-backoff reconnect.
2. `mute-app` action.
3. `app-volume` action; `delta = ticks × step`, fine step when `pressed`.
4. The three degraded states, each distinct and honest.

### Phase C3: Property Inspector and packaging

1. `sdpi-components` selects backed by a `getApps` data source.
2. Node tests for the client against a fake server.
3. `streamdeck pack`; document `streamdeck link` for local testing.

## Definition of done

- `swift build` and `swift test` green; no test skipped or weakened.
- Every capability in the feature inventory verified unchanged.
- New load-bearing tests mutation-checked: reintroduce the bug, confirm failure.
- Version `1.4.0`, build `8`, consistent across build script, workflow and cask.
- Waves' side demonstrable from Terminal via `wavesctl` with no Stream Deck.
